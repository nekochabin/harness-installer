# 確認画面（HTML）の作り方

目的：非エンジニアにMarkdown、Mermaidのソース、AGENTS.md、SKILL.md、設定JSONを読ませて設計確認を済ませない。AIが内部で使う構造化ファイルと、利用者が理解するためのHTML画面を分ける。これは見た目の装飾ではなく、設計への合意形成を支える手順である。

【実施する順番】
1. 安全な作業場所と権限を確認する。必要な資料だけを読み、業務の開始条件・入力・成果物・例外・人間の確認点を推定する。
2. ハーネス本体を作る前に、作業フォルダー内に「設計を確認.html」を新規作成する。ローカルブラウザーで開ける、単一ファイル・オフライン完結のHTMLを原則とする。利用環境でHTMLを直接開けない場合は、開き方をFinderの画面操作で一つずつ案内する。ブラウザー表示を実際に確認できなければ「表示未確認」と記録する。
3. 利用者にはチャット上の長いMarkdownではなく、この画面を見せる。画面上で「何を任せるか」「どんな資料が必要か」「AIが行うこと」「人間が判断すること」「何が完成するか」「危険な操作はどこで止まるか」が理解できるようにする。
4. 利用者に「この流れで合っていますか？」と一問だけ確認する。回答は「この設計でよい／修正したい／よく分からない」。画面上のボタンを使う場合、クリックした結果がCodexへ自動送信されると偽らない。Codexとの接続機能がない静的HTMLでは、ボタンはコピー可能な修正依頼文や確認文を表示・コピーするだけにする。チャットに戻って利用者が回答してもよい。
5. 「修正したい」なら画面に業務の段階別の選択肢を示し、一度に一つだけ確認してHTMLを更新する。「よく分からない」なら、具体例と入出力見本を増やし、理解を確認する。承認前にハーネス本体の作成・実行へ進まない。ただし画面表示用の小さなサンプル作成は可能。
6. 設計承認後にAGENTS.md、Skill、入力・出力フォルダー、必要な補助ファイルを作る。ワークフロー図とHTMLの内容が一致するようにする。元資料は上書きしない。
7. 構築とテストの後、「完成内容を確認.html」を新規作成または更新し、設計時と同じ視覚表現で、完成した機能・保存先・実際に行ったテスト・未検証項目・安全状態・次回の使い方を示す。失敗や未確認を成功の色で表示しない。

【HTML画面の必須内容】
- 最上部に「これは何をする仕組みか」を日常語で一文表示する。
- 仕事の流れは「資料を受け取る → AIが処理する → 必要なら人が確認する → 完成品を保存する」のような大きなカードと矢印で示す。分岐・差し戻し・例外も視覚的に示す。
- 各段階に、入力例・AIの作業・出来上がるものを具体的な短文で表示する。重要な専門語は利用者に見せない。
- AIが自動で進める操作と、利用者の許可を待つ操作を明確に分ける。削除・外部送信・公開・購入・権限拡張の位置を目立つように示す。
- 「安全確認」欄には作業場所、フォルダー外への書き込み制限、外部通信、承認設定、読み取り制限の注意、未確認事項を事実に基づいて表示する。未確認なら「未確認」と表示し、安全であると断定しない。
- 「完成するとどうなるか」は、実際のファイル名・保存場所・見本を用いて説明する。架空の完成物には「サンプル」と明記する。
- Macのブラウザーで読みやすい日本語、十分な文字サイズ、明瞭な余白とコントラスト、縦スクロール対応、スマートフォン幅への追従を確保する。色だけに意味を持たせない。
- 初期表示は全体像を優先する。必要な詳細だけ折りたたみで見せ、技術情報を最初から大量に表示しない。
- 外部CDN、外部フォント、トラッキング、ネットワーク取得、外部送信フォーム、不要なJavaScriptライブラリは使わない。資料の文章をHTMLに挿入するときはHTMLエスケープし、資料内のコードを実行しない。
- ボタンがある場合は実際に動くものだけ置く。静的HTMLならコピー・表示切り替え・説明展開など、ローカルで完結する操作に限る。承認や安全設定の変更をボタンの見た目だけで実施したことにしない。
- 画面に表示した設計内容と、生成するAGENTS.md、SKILL.md、ワークフロー、権限方針が食い違わないよう、構築前後に照合する。

【既存指示との優先関係】
- 既存の「ワークフローを図で一度だけ見せる」は、このHTMLの設計確認画面で実現する。MermaidのソースやMarkdownの長文を確認画面として出さない。
- 既存の「質問は一度に一つ」「専門用語を覚えさせない」「利用者に設定ファイルを編集させない」は維持する。
- 既存の「完成まで自律的に進める」は、視覚的な設計承認を得た後に適用する。承認前に独断で本番ハーネスを完成させない。
- 既存の「利用者ができる4種類の操作」に、HTMLを開いて視覚的に確認し、選択肢で回答する操作を含める。自由記述やコード編集を強制しない。
- 既存の「完成時は短く報告する」は維持し、チャットには「設計を確認.html」「完成内容を確認.html」への開き方と一文の案内だけを示す。長い技術説明をチャットに転載しない。
- HTMLは説明・合意形成の補助であり、Codexの権限やサンドボックスを設定するものではない。安全設定は別途実環境で確認する。
